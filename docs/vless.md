## 1. VLESS 协议请求报文二进制布局

VLESS 是一种无状态的轻量级代理协议，客户端在 WebSocket 建立后通过二进制帧向服务端传输首包请求头：

```text
+---------+----------------+---------+--------+---------+--------+-------------+---------+---------+
| Version |      UUID      | AddonsL | Addons | Command |  Port  | AddressType | Address | Payload |
| (1 B)   |    (16 B)      |  (1 B)  |  (M B) |  (1 B)  | (2 B)  |    (1 B)    |  (N B)  | (剩余)  |
+---------+----------------+---------+--------+---------+--------+-------------+---------+---------+
```

### 字段详细说明
1. **Version (1 Byte)**: 协议版本号，通常固定为 `0x00`。
2. **UUID (16 Bytes)**: 客户端的用户凭证（16 字节原始数据），转换为 36 字符的标准规范小写 UUID 格式（`8-4-4-4-12`）。
3. **Addons Length $M$ (1 Byte)**: 附加信息长度。通常为 `0x00`；若 $M > 0$，紧随其后的 $M$ 字节为附加元数据。
4. **Command (1 Byte)**: 路由指令。
   - `0x01`: TCP 出站代理
   - `0x02`: UDP 出站代理
   - `0x03`: MUX 复用
5. **Port (2 Bytes)**: 目标端口号（大端序网络字节序，取值范围 `1 ~ 65535`）。
6. **Address Type (1 Byte)**: 目标地址编码类型：
   - `0x01` (IPv4): 紧随 4 字节，反序列化为点分十进制字符串（如 `"1.1.1.1"`）。
   - `0x02` (Domain): 紧随 1 字节长度 $L$ + $L$ 字节 ASCII/UTF-8 字符（如 `"example.com"`）。
   - `0x03` (IPv6): 紧随 16 字节，反序列化为 8 组十六进制冒号分隔格式（如 `"2606:4700:0:0:0:0:0:6810"`）。
7. **Payload (剩余字节)**: 应用层握手载荷（如 TLS ClientHello 等），在头部截断提取后作为独立的 `Uint8Array` 返回。

## 2. 纯函数设计原则 (`vless/parser.ts`)

为保证解析层可移植性及 100% 本地单测独立性，[`worker/src/vless/parser.ts`](file:///Users/Apple/Projects/tools/cf-vless/worker/src/vless/parser.ts) 严格遵循以下架构原则：

- **严格无副作用**：纯内存切片运算，严禁调用任何网络 I/O、全局存储或外部环境变动。
- **确定性输出**：输入相同 `Uint8Array` 保证恒定产出相同的 `VlessRequest` 结构体或确定异常。
- **零额外拷贝**：对大载荷应用数据，优先利用 TypedArray 视图切片（`subarray`），避免无谓的内存深拷贝消耗。

## 3. 防溢出与安全截断校验

解析器针对各种恶意畸变数据或网络截断包部署了多重防御屏障：

1. **绝对下限长度校验**：报文总长度必须 $\ge 24$ 字节（1 + 16 + 1 + 0 + 1 + 2 + 1 + 2 最小地址），否则拒绝。
2. **Addons 边界校验**：检查声明的 Addons 长度是否超出剩余缓冲区；检查跳过 Addons 后的指令与端口元数据是否完整。
3. **指令与端口校验**：拒绝非法 Command（非 1/2/3），拦截端口 `0` 或超过 `65535`。
4. **域名截断攻击防护**：校验域名标称长度 $L > 0$，且剩余缓冲区字节数必须 $\ge L$，彻底杜绝越界读取。
5. **IP 长度校验**：严格校验 IPv4 需满 4 字节、IPv6 需满 16 字节。

## 4. 自动化测试矩阵 (`test/vless.spec.ts`)

单元测试实现了 100% 覆盖率，涵盖以下维度：

- **正向目标测试**：
  - 标准 IPv4 目标解析（`1.1.1.1:53`，UDP）
  - 标准域名目标解析（`example.com:443`，TCP）
  - 标准 IPv6 目标解析（`2606:4700:0:0:0:0:0:6810:443`）
  - 空载荷包（Payload 长度为 0）
  - 大数据初始载荷包（携带 4KB TLS ClientHello 数据保持字节完整）
  - 带 Addons 载荷包（$M = 5$ 正确偏移跳过）
  - 端口极值（`1` 与 `65535`）
- **反向容错与畸变测试**：
  - 空 / 残缺包（`< 24` 字节）
  - Addons 长度虚标溢出包
  - 非法 Command 指令（0, 4 等）
  - 非法端口（`port: 0`）
  - 未识别地址类型（非 1/2/3）
  - 域名长度为 0 异常包
  - 域名长度虚标截断包（声明 50 字节实际仅有 5 字节）
  - IPv4 / IPv6 数据不全截断包
- **工具纯函数测试**：
  - `formatUuid` 16 字节转标准 36 字符规范 UUID。
  - `formatIpv6` 16 字节转 8 组十六进制格式。

## 5. UUID 鉴权与短路防御机制 (Step 7)

### 恒定时间防御 (`timingSafeEqual`)
由于标准字符串严格比较（`===`）在发现首个不匹配字符时会提前跳出循环，可能遭受侧信道时间差分析（Timing Attack）。
在 [`worker/src/vless/auth.ts`](file:///Users/Apple/Projects/tools/cf-vless/worker/src/vless/auth.ts) 中实现了无分支位异或运算的恒定时间比较算法，彻底抹除时间侧信道指纹。

### 鉴权拦截与生命周期
1. **未授权请求立即阻断**：当客户端首包解析出的 UUID 与环境变量 `VLESS_UUID` 不匹配时，服务端立即通过 `server.close(1008, "Policy Violation: Invalid User UUID")` 关闭连接。
2. **零网络副作用保证**：鉴权失败的连接在首包解析阶段直接被切断，严禁触发后续出站 TCP 发起与任何平台资源消耗。
3. **协议就绪确认**：鉴权通过后，服务端下发标准的 VLESS 响应首部 `new Uint8Array([0, 0])`，标志着代理链路已就绪。
